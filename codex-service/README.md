# Codex 任务中心

CK 侧栏的「Codex 任务」与「Codex API 配置」连接独立的 VPS 服务。
未登录聊天网关时，也可从登录页的「Codex 任务中心」或 `#codex-tasks` / `#codex-api` 链接进入。窗口确认框独立，聊天网关原有鉴权保持有效。
后端使用官方 Codex app-server 的 stdio 协议，监听回环 19007，由 HTTPS `/codex/*` 转发；没有网关代码依赖。

每个窗口使用独立 CODEX_HOME 和真实 thread ID。新建、关闭后恢复、永久删除都操作对应 Codex 会话；删除也清除该窗口的本地历史。关闭网页不终止任务。不同窗口并行执行，每个窗口最多一个任务；等待回复不会阻塞其他窗口。同一执行中窗口可追加指令，支持停止及回答 Codex 的问题。

v1.2.0 的 `any_retry.py` 只绑定现有 any 供应商的配置编号。选择 any 后手动提交任务，即为本次任务启用无限次过载重试：等待本轮明确失败，每次随机等待 1～10 整秒，再在同一原生会话中继续未完成任务。保留最初任务及追加指令、工具结果，不从头重放已完成操作。其他供应商沿用原行为。any 的 CLI 内置固定退避重试设为 0，由本脚本统一调度；网络请求本身的耗时不包含在随机等待中。

面板只在同一条记录更新「已重试 N 次」，不逐次追加过载报错。任务完成、停止、关闭、删除或服务重启都会结束本次重试；单独重新打开窗口或刷新页面不会启动任务，需要再次手动提交。关闭网页仍可后台执行。密钥、权限、余额等明确配置错误及无法确定任务是否已启动的本地 RPC 超时保留为失败，不重复提交。脚本没有开机启动、定时扫描旧失败任务或自动重发历史任务的入口。

文字进展和回复完整保存，命令、文件差异与工具信息默认完全折叠，问题醒目显示。任务接口、推理强度和模型通过独立顶层弹窗选择，支持模型搜索及手动输入。

文字进展、命令输出、文件差异、计划、最终回复和错误保存到 SQLite，通过带游标的读取补收。客户端提交使用稳定请求编号，断线重试不重复排队。服务重启将执行中的任务标为中断，不自动重新执行可能已产生副作用的命令。只展示模型提供的简短思考摘要，不保存或展示原始推理事件。

API 配置与访问密钥独立存放于 `/var/lib/ck-codex/config.json`（0600）。GET 接口不返回模型密钥，密码留空保留原值。配置变化不打断正在执行的任务，下次执行重建所需进程。公网只允许 HTTPS；服务端检查访问密钥及浏览器 Origin。

备份遵循每个任务一个本机单元：`task_backup.py` 只收明确指定的必要文件，已有 Git commit/release 只记录引用。没有全库定时打包或跨机器重复备份。

部署运行环境：Python 3.10+、Linux、Codex CLI 0.162.1。`CK_CODEX_STATE`、`CK_CODEX_WORKSPACE`、`CK_CODEX_BIN`、`CK_CODEX_PORT` 可设置独立测试环境。服务不安装到 Python 网关目录，避免依赖及状态混用。

验证：`python -B tests/codex-service.test.py`；`node --check codex-tasks.js`；安装 Playwright Chromium 后执行 `node tests/codex-ui.test.js`。
另外执行真实 CLI 创建/恢复/删除、API 只读任务，以及 320/390/1360 像素浅/深色浏览器验收。
